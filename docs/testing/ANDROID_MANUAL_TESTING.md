# Android 人工验收：接收端预览包

设备由使用者操作，不需要开放 ADB、远程桌面或账号权限。开发者提供可安装
APK、对应提交、SHA-256、测试步骤和已知限制；使用者回传结果后才能记录真机通过。

## 当前包的边界

这是 Android 8.0/API 26 及以上、ARM64（`arm64-v8a`）的开发签名预览包，
不是商店版或 Stable 版本。当前只验收安装、Rust JNI 加载、接收服务生命周期
和授权设置。**尚不能用它验收真实画面/声音、DLNA 或 AirPlay 投屏成功。**
本页是早期接收端生命周期检查清单。匹配的新预览已另有[Native 测试流](ANDROID_REFERENCE_SENDER.md)、
[真实屏幕共享](ANDROID_SCREEN_CAPTURE.md)和[发送端身份验证](ANDROID_SENDER_IDENTITY.md)步骤；
不要把本页的生命周期通过当成这些新流程的验收。

开发签名包若与设备上已有包的签名不同，会安装失败；请先报告，不要为了覆盖
而直接卸载。卸载会删除本应用的信任记录和设置。不要向本预览包授予不相关权限。
只安装随交付记录提供的包，不要使用来源不明的二次打包版本。

## 本轮步骤（约 5 分钟）

1. 记录设备型号、Android 版本和是否为手机/电视。安装提供的 APK 并打开。
2. 确认首页显示 `Rust core ABI 1 loaded`，而非 unavailable/mismatch。
3. 没有发送端连接时，批准/拒绝当前 proof 的按钮应禁用。
4. 在停止状态点 `Require verified sender proof`，应提示模式已开启。
5. 点 `Start receiver service`，随后点 `Refresh pairing info`，应看到临时
   FANP 端口和配对码。配对码只在本机查看，不要回传或截图公开。
6. 运行时点 `Use PIN-only pairing (while stopped)`，应提示先停止接收器，
   不能在运行中切换模式。
7. 点 `Stop receiver service`，再刷新，配对信息应消失。停止后再次选择
   PIN-only 应成功。
8. 重复启动/停止 5 次。把应用切到后台再返回，记录是否崩溃、卡死或状态异常。
   测完后明确停止服务，不需要长时间让它后台运行。

## 回传模板

```text
APK 文件名/交付提交：
设备型号 / Android 版本 / 手机或电视：
安装：通过 / 失败（系统提示）
Rust 加载：通过 / 失败（提示）
步骤 3–8：分别通过 / 失败（步骤编号、预期与实际差异）
重复次数：
异常：闪退 / 卡死 / 无异常 / 其他
```

截图请遮盖配对码、IP、设备身份/指纹和通知中的私人信息。不要发送私钥、
账号凭据、完整网络抓包或个人媒体。本轮结果只计入上述功能的设备证据，
不计入 M1 1080p30、M2 1080p60/一小时稳定性或 M3–M5 协议兼容验收。
